# 第 4 步 · 采样：看看 AI 现在怎么说你

**目的：** 拿到"用户真实看到的回答"，作为诊断和复查的基线。

由用户亲手在目标 AI 里提问，再把回答复制给你。本流程不自动登录或抓取 AI 产品的页面；也不要用 API 回答冒充 App 实测。

## 开始前固定批次

为本次采样创建唯一批次（例如 `2026-10-14-doubao-baseline-01`），在 `geo/runs/<批次>/` 保存 `questions.csv`、`fact-card.yaml` 快照及 `batch.md`。在 `batch.md` 记录目标平台、入口、时区、计划题数与次数、问题集版本和事实卡版本。版本可用快照文件名和日期，开始后不要修改快照；产品事实变化另建版本。样本数未达计划时也如实诊断，不补造回答。

## 给用户的操作说明（照着发给用户）

> 请在 **[目标 AI]** 里问下面 10 道题，每道题问 **2 次**：
> 1. **每次都开一个新对话**，不要在同一个对话里连着问。
> 2. 界面有**联网搜索**开关就开启，并记录设置；没有开关或看不出是否搜索，就写“未知”，不要默认开启。记录可见的模式或模型名称。
> 3. 问题**一个字都不要改**，直接复制粘贴。
> 4. 把**整段回答**复制回来；回答下方或旁边如果有"参考资料""引用""来源"，也点开，把来源的标题和链接一起复制回来。
> 5. 第一次贴回时顺便告诉我：用的是 App 还是网页、有没有登录、采样日期和时区、大概在哪个城市（不便提供可写“未提供”）。
>
> 一共 20 次，大约 15 到 20 分钟。可以分几次贴给我。

用户想更扎实，可以加题、加次数（每题 3 次以上）或加 AI。告诉他"样本越多，结论越可靠"，但不要强制。

## 你收到回答后

1. 每个回答原文存成 `geo/runs/<批次>/Q01-1.md`（问题编号加轮次），开头单列平台、日期、时区、入口、模式、联网设置、登录和地区，随后分别保存原始问题、回答全文、来源标题和原始 URL。**原文一个字都不改**；分析放在单独区域。`run_id` 用“批次-Q01-1”，不得覆盖已有记录。
2. 在 `geo/runs.csv`（格式见 [assets/runs.csv](../assets/runs.csv)）记一行：
   - 是否提到我们：是 / 否 / 未知；技术失败或原文不完整时写“未知”
   - 位置：第几个被提到；没有列表就写"正文提及"
   - 描述是否正确：对照本批次事实卡快照，写 对 / 部分错 / 错 / 未涉及 / 未知；来源冲突或事实卡未确认时写“未知”，不能凭常识判对
   - 错误内容：错在哪，对应事实卡哪条
   - 引用来源：每个来源的域名或平台（如 知乎、公众号、百度百科、CSDN、官网），用分号隔开
   - 批次、问题集版本、事实卡版本、原文路径：对应本次快照和实际文件
   - 回答状态：完整 / 拒答 / 技术失败 / 不完整 / 未运行 / 未知
   - 排除是否正确：C 类写 对 / 错 / 未知；其他类写“不适用”。按题目预先约定的判定标准，不能只因没有提到品牌就判“对”；拒答、答非所问不能算正确排除
   - 来源状态：已提供 / 界面无来源 / 待补充 / 未知。回答没有引用不等于原文不完整
   - 是否推荐我们：推荐（作为建议选项列出或明确建议使用）/ 仅提及（出现了但没被推荐，例如只在对比里带过或被说不适合）/ 否 / 未知
   - 推荐了谁：回答里**被推荐的所有品牌**，按出现顺序用分号隔开，包括我们自己。这一列是找竞品缺口的依据，A 类题必填
3. 用户贴的回答明显截断时，状态写“不完整”，请他补全；来源未贴则单独标“待补充”。正文完整但没有来源仍可计入提及和正确性指标，不能把无引用的回答删掉。
4. 完整拒答属于有效产品输出，保留在分母；按实际正文记录是否提及，拒答本身不计答对或排除正确。网络报错、额度不足且未生成完整答复等记“技术失败”，不可推断为“没提到”。技术失败、不完整、未运行和未知不进有效回答分母，但必须报告各自数量。补跑另记新轮次，不替换失败记录，也不反复问到满意为止。
5. CSV 中包含逗号、双引号或换行的单元格要用双引号包裹，内部双引号写成两个双引号。旧版 CSV 保留原文件，另存补齐新表头的副本；无法从原始证据还原的字段写“未知”，不能猜批次、状态或正确性。

## 自动采样：用 API 批量问（可选）

用户有某个 AI 的 API Key、想省掉手动提问，或想每周看一次趋势时，用 `scripts/geo-probe.mjs`（零依赖 Node.js 脚本）自动提问。它**补充**人工采样，不替代：API 回答不登录、系统提示也不同，和用户在 App 里看到的可能不一样。联网方面：Perplexity、Kimi（内置 `$web_search`，每次搜索另计少量费用）和通义千问（`enable_search`）会联网搜索，其他接口多数不联网。

1. 先确认 `geo/questions.csv` 里的题已经填好（模板占位题会被跳过），并问清用户的品牌别名和主要竞品。
2. 请用户在**自己的终端**设置 API Key 环境变量（如 `DEEPSEEK_API_KEY`、`DASHSCOPE_API_KEY`、`MOONSHOT_API_KEY`、`ARK_API_KEY`、`OPENAI_API_KEY`、`PERPLEXITY_API_KEY`、`GEMINI_API_KEY`、`ANTHROPIC_API_KEY`）。**不要让用户把 Key 发到对话里，也不要写进任何文件。**
3. 先演练，确认题数和请求次数：

   ```bash
   node scripts/geo-probe.mjs run geo/questions.csv --ai deepseek,qwen --brand "品牌,别名" --competitors "竞品甲/英文名,竞品乙" --dry-run
   ```

   去掉 `--dry-run` 正式跑。默认每题 2 次；`--ai 名称:模型` 指定模型（豆包必须填方舟的模型 ID 或接入点 ID）；`--only A` 只问 A 类题；其他接口用 `--ai custom --base-url … --key-env … --ai custom:模型`。
4. 每个 AI 单独成一个批次（如 `2026-10-16-deepseek-api-01`），原文、快照和 `summary.md` 写进 `geo/runs/<批次>/`，索引追加到 `geo/runs.csv`，`入口` 列固定写 `API`。
5. **复核初判。** 脚本按关键词初判"是否提到我们""是否推荐我们""推荐了谁"，只认得 `--brand` 和 `--competitors` 里的品牌。逐条打开原文复核：改正误判，把回答里其他被推荐的品牌补进"推荐了谁"，B 类填"描述是否正确"，C 类填"排除是否正确"，备注里写"已复核"。没复核完的批次在诊断里注明"自动初判"。
6. 复核后用 `node scripts/geo-probe.mjs report geo/runs.csv --batch <批次>` 重新算五个数和竞品推荐榜；不带 `--batch` 时按批次、平台、入口分组汇总全部记录（含人工采样）。

API 批次和 App 批次**分开报告，不合并计算**。可以说"DeepSeek API 20 次里推荐 3 次"，不能说成"DeepSeek App 推荐率 15%"。

## 为什么每题要问 2 次

同一个问题，AI 每次的回答都可能不同。两次用于初步观察波动，不足以证明统计显著性。诊断报告实际提及次数和有效回答数，不把单次排名当成稳定结果。

## 完成标准

- 10 道核心题 × 2 次的计划逐项记录；未完成和失败也保留，收到的原文全部存档，`geo/runs.csv` 填完
- 报告计划次数、有效回答数（其中拒答数）、技术失败数、不完整及未运行数；再说明有效回答中提到和说错几次，进入诊断
