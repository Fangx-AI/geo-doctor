# 第 3 步 · 问题基线：用户会怎么问 AI

**目的：** 定下要问 AI 的那批问题，并且能证明这批问题值得问。问题集一旦冻结，复查时一个字都不改，否则前后没法比。

**铁律：问题集本身是测量的一部分。** 同一份 brief 换一套问法，结论会变；所以"问了什么"必须和"答案是什么"一起记录。

## 为什么不能随手编 20 道题

三条有出处的证据（核验于 2026-11-17）：

1. **换题会换结论。** 一份预注册研究把同一份需求写成 6 套 prompt frame，其中 3 套问的是同一个对象，测 46 个品牌；**frame 之间的差异大于被测对象本身的差异**。结论：构造规则必须写下来并可复现，不能"我感觉这样问更自然"。<br>来源：[The Prompt Set Is Part of the Measurement](https://zenodo.org/records/23459844)（2026-10-18 预印本，附 reproduction pack）
2. **问法决定 AI 到底有没有去检索。** 90 条真实用户提问里，**商业意图有 78.3% 触发了 query fan-out，信息型只有 3.6%**。结论："什么是 X""X 是什么"这类题测的是模型记忆，不是你页面被读到的能力。<br>来源：[From Prompt to Recommendation](https://arxiv.org/abs/2609.23162)
3. **题量比重复次数更值钱。** 在 137 个 brand×cell 观测里，**44.5% 五次采样全都出现、24.8% 只出现一次**；要把区间压到 ±10 个百分点、并且能周与周比较，需要每个 prompt 每个引擎约 **100 次采集**。结论：与其 10 道题各问 10 次，不如 100 道题各问 1 次。<br>来源：[AI Visibility Sample Size](https://www.scrapeless.com/en/blog/ai-visibility-measurement-sample-size)

所以这一步的产出不是"一堆问题"，而是**一份能被人复核的题集**：每道题有类型、有形状、有限定条件、有来源、有证据等级、有判定标准，并且能机械检查。

## 三个正交坐标

同一道题同时落在三个坐标上，别只用一个维度分类：

| 坐标 | 取值 | 决定什么 |
| --- | --- | --- |
| 意图类型 | A 不带品牌的推荐 / B 品牌事实 / C 不适合场景 / D 使用排错 | 这道题能证明什么 |
| 问法形状 | 认知定义 / 品类发现 / 选型推荐 / 直接对比 / 找替代 / 预算约束 / 实施集成 / 排错 / 合规风险 / 本地时效 | AI 会不会去检索、会不会给榜单 |
| 限定条件 | 预算、人数、规模、行业、地区、平台、合规要求 | 答案有没有区分度 |

形状的写法和各自陷阱见 [question-shapes.md](question-shapes.md)。限定条件不是装饰：没有限定条件的 A 类题（"什么笔记软件好"）对所有人返回同一张泛榜，对你的品牌没有区分度。

## 两层题集

| 层 | 数量 | 能不能改 | 用来干什么 |
| --- | --- | --- | --- |
| **仪表题（核心）** | 12–18 道 | **冻结**，改了就是新基线，旧数据不混算 | 报率、报趋势、做前后对比 |
| **雷达题** | 10–20 道 | 每轮可以换 | 发现新场景、新竞品、新问法 |

仪表题是要写进报告给人看的数字来源；雷达题是探索，不进趋势表。两者都放同一个 `geo/questions.csv`，用「优先级」列区分（`核心` / `一般`）。

## 题目从哪来：证据等级 1–5

| 等级 | 来源 | 写法 | 能当仪表题 |
| --- | --- | --- | --- |
| 1 | 真实对话原话：客服记录、销售聊天、用户访谈、工单 | 工单号或日期 | 最佳 |
| 2 | 社区原话：知乎问题、小红书、V2EX、Reddit、应用商店评论 | 实际链接或帖子标题 | 可以 |
| 3 | 平台追问与搜索下拉：百度/微信/Google 下拉词与相关搜索、AI 回答后的推荐追问 | 平台 + 关键词 | 可以 |
| 4 | 公开数据转写：Search Console 里**高曝光低点击**的查询、站内搜索词、竞品评论区 | 数据源 + 时间范围 | 少用 |
| 5 | 构造：按事实卡编，或为覆盖某个形状而写 | 必须标「构造」并写依据的事实编号 | 占比要低 |

规则：

- 仪表题里 1–3 级合计**至少一半**。
- 5 级题整体**不超过 40%**，且在报告里必须写明"这批是假设题集，不代表真实需求分布"。
- 用户说不出原话时，**照抄用户的说法**，别改写成营销腔："有没有不用联网也能记笔记的软件"就照这个写，不要改成"离线笔记解决方案推荐"。

## 配额（按仪表题算）

| 类型 | 占比 | 12 道时 | 18 道时 |
| --- | --- | --- | --- |
| A 不带品牌的推荐 | 约 40% | 5 | 7 |
| B 品牌事实 | 约 30% | 3–4 | 5 |
| C 不适合场景 | 约 20%，且不少于 2 道 | 2–3 | 3–4 |
| D 使用排错 | 约 10% | 1 | 2 |

形状至少覆盖 5 种。A 类题里**绝对不能出现自己的品牌名**——出现了就不再是"没听过你时会不会被推荐"，而是认词测试。

## 两个坐标：场景 × 旅程

题集最容易犯的错不是题不好，是**全都挤在一格**：二十道都在问"哪家好"，客户真正下决定的那几步一道题都没有。

- **场景**：客户在什么处境下遇到你。从事实卡里的分区、服务、人群派生，不要从行业模板抄。
- **旅程**：探索 / 选型 / 对比 / 口碑。四段读的是四件不同的事（被引用 / 进名单 / 对位胜率 / 情感倾向），所以不能合并成一个平均数。

```bash
node scripts/geo-probe.mjs matrix geo/questions.csv
```

输出是一张「场景 × 旅程」表，`—` 就是下一步该写的地方。先补**选型**那一列（客户真正在挑的时刻），再补**对比**（只有对比题能分清"被顺带一提"和"被正面对比"），口碑至少每场景一条（不直接问品牌，就永远不知道 AI 怎么描述你）。

`—` 是合法答案：某些场景确实没有某个阶段，空着比硬凑好。做法与两种"假矩阵"见 [scenario-matrix.md](scenario-matrix.md)。

## 每题要填的十二列

格式见 [assets/questions.csv](../assets/questions.csv)（模板行用括号占位，工具会自动跳过）：

| 列 | 填什么 |
| --- | --- |
| `id` | Q01 起，冻结后不变 |
| `类型` | A / B / C / D + 一句说明 |
| `形状` | 十种形状之一 |
| `问题` | 用户原话，含限定条件 |
| `判定标准` | 什么算提到、什么算推荐、什么算答对 |
| `对应事实` | 事实卡编号（F01…），B 类必填 |
| `优先级` | `核心`（仪表题）/ `一般`（雷达题） |
| `来源类型` | 客服 / 社区 / 搜索下拉 / 平台追问 / 构造 … |
| `来源` | 工单号、链接、平台关键词；构造题写依据的事实编号 |
| `证据等级` | 1–5 |
| `场景` | 客户在什么处境下问（可留空，留空就进不了矩阵） |
| `旅程` | 探索 / 选型 / 对比 / 口碑 |

## 机械检查：先体检，再采样

```bash
node scripts/geo-probe.mjs check geo/questions.csv --brand "你的品牌,别名"
```

它检查的都是能机械判定的事，没有一条是文风意见：

- 题量与核心题数量是否落在 12–40 / 12–20
- A/B/C/D 配比是否在 ±10 个百分点内；**C 类为 0 直接 fail**
- 类型是否只用了 A–D；每题的证据等级是否 1–5
- **A 类题里是否出现自己的品牌名**（fail）
- 去掉标点空格后是否完全重复（fail）；字符二元组相似度 ≥85%（warn）
- 是否带诱导措辞（"请推荐""最好的""哪家最好"）（warn）
- A 类题是否缺限定条件（warn）
- 每题是否有判定标准、是否有来源（warn）
- 构造题占比是否超过 40%、核心题里构造占比是否超过一半（warn）
- 形状是否少于 5 种（warn）
- 矩阵覆盖了多少格、哪个场景缺选型题、是否整段缺失（warn）

`fail` 有就退出码 1：**这时候采样出来的数不能用**。`warn` 不阻塞，但要在报告里写清为什么保留。

## 冻结与版本

冻结的不只是题目文字，还有：类型、形状、判定标准、品牌词表（含别名写法）。冻结动作要做三件事：

1. 采样时 `geo-probe run` 会自动把当次的 `questions.csv` 快照存进 `runs/<批次>/`，这就是版本证据，别删。
2. 在报告里写清基线日期与题集 id 范围（例如"v1 基线，Q01–Q16，2026-11-17"）。
3. 改题就是新基线：新题用新 id，旧数据不与新题混算；跨基线比较只在共享的题目上做。

## 别做的事

- 只问品牌词（"XX 好不好用"）：测的是已有认知，不是新增曝光。
- 用"最好的 X""请推荐"开头：AI 直接给榜单，测不出自然浮现。
- 一道题问两件事（"多少钱，支持导出吗"）：答对一半时没法判。
- 拿 10 道题各问 10 次当"更可靠"：题的覆盖面才是分母，见上文第 3 条证据。
- 把模板里的括号占位题直接拿去采样：会被跳过，报告里会出现空列。

## 完成标准

- `node scripts/geo-probe.mjs check geo/questions.csv --brand "..."` 退出码 0，无 fail
- 仪表题 12–18 道，A/B/C/D 配比在目标 ±10 个百分点内，C 类不少于 2 道
- 至少 5 种问法形状，A 类题全部带限定条件且不含品牌名
- 矩阵里每个场景都有选型题；对比和口碑不是整段空白（空白要么补，要么在报告里写明为什么这个场景不需要）
- 每道题都有判定标准与来源；构造题标注清楚且有依据
- 告诉用户："这批题冻结了，下一步我们去 [目标 AI] 里问，采样结果按题号记录"
