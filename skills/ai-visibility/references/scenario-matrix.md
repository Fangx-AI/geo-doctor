# 场景 × 旅程矩阵：先看哪里是空的，再写题

一份问题清单最容易犯的错不是"题不好"，是**全都挤在一格**。二十道题全在问"哪家好"，测出来的是一个数；而客户真正下决定的那几步，可能一道题都没有。

矩阵的作用是把这件事摆到桌面上。两个轴：

**场景**：客户在什么处境下遇到你。从知识库（或事实卡）里的分区、服务、人群派生，不要从行业模板抄 —— 抄来的场景往往跟这家店实际卖的东西对不上。

**旅程**：他在决策的哪一段。
- **探索**：还不知道要什么，先搞清楚品类和判断标准。读"你的内容有没有被引用"。
- **选型**：在几个候选里挑，通常带地名、预算、人数。读"进不进名单、排第几"。
- **对比**：把两三家放一起比。读"对位胜率"（被顺带一提，还是被正面对比）。
- **口碑**：直接问某个品牌可不可靠。读"情感倾向与负面拦截"。

四段读的是四件不同的事，所以不能合并成一个平均数。一家店可以在口碑段完胜，却在选型段一次都不出现 —— 那它就没有新客。

## 怎么用

1. 先把场景列出来（通常 5–10 个），每个场景问一句"人在这个处境下会怎么开口"。
2. 每个场景先补**选型**那格：那是客户真正在挑的时刻，也是本地生意绝大多数成交发生的地方。
3. 再补**对比**：只有对比题能看出 AI 是把你顺带一提，还是真的拿来对位。没有竞品名的对比题不算。
4. **口碑**至少每个场景一条：不直接问品牌，就永远不知道 AI 怎么描述你，负面也没人拦。
5. `—` 是合法答案：某些场景确实没有某个阶段（例如"双人约会"没有对比需求），空着比硬凑好。

## 本地生意多一个轴

带地名的题要再乘一次地名（城市 / 区 / 商圈 / 地铁站）。同一个意图在不同商圈是不同的问题，也会命中不同的答案。这是通用 GEO 工具通常没做的部分，也是本地店唯一的结构性差异。

地名别只写城市：`杭州` 太宽，`杭州下沙大学城` 才有区分度。

## 用工具检查

```bash
# 体检：题量、类型配比、证据等级、重复、A 类题里的品牌名，以及矩阵覆盖率
node scripts/geo-probe.mjs check questions.csv --brand "你的品牌,别名"

# 只看矩阵：空格就是下一步该写的地方
node scripts/geo-probe.mjs matrix questions.csv
```

`check` 会为每个缺选型题的场景报一条 warn，并在整段缺失（对比或口碑一道都没有）时另报一条。`matrix` 输出的表可以直接贴进方案。

## 两种常见的假矩阵

- **一行八个场景，四列全是"选型推荐"**：看着整齐，其实只有一个轴在工作。看看四个旅程列是不是都有人。
- **每题都标"核心"**：核心题是用来做前后对比的仪表，12–18 道就够；全标核心等于没有核心。

## 冻结与复查

矩阵搭好后，把标了「核心」的题冻结成这一轮的仪表题（12–18 道），其余作为雷达题。下一轮可以换雷达题去探新场景，仪表题不动 —— 动了，两轮的数字就不能比。
