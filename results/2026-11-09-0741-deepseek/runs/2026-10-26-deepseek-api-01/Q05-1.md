# Q05 · 第 1 次

## 问题

小团队没有服务器，怎么做 GEO？

## 回答

小团队没有服务器，做 GEO 其实反而有优势——**GEO 的核心不是技术基建，而是内容被 AI 引用的概率**。没有服务器意味着你不需要维护后端，可以完全依赖 SaaS 和静态托管。下面是一套可落地的方案。

## 先明确：GEO 在无服务器场景下的含义

GEO（Generative Engine Optimization）指让内容更容易被 ChatGPT、Perplexity、Google AI Overviews、Kimi、豆包等生成式引擎**抓取、理解、引用**。关键是：

1. 内容可被爬虫访问（不需要服务器，静态站即可）
2. 内容结构对 LLM 友好（结构化、有事实密度）
3. 有权威信号（外链、引用、实体一致性）
4. 能被 AI 索引源覆盖（部分引擎依赖 Bing/Google 索引）

## 一、基础设施：零服务器方案

| 需求 | 无服务器方案 |
|---|---|
| 网站托管 | Cloudflare Pages、Vercel、Netlify、GitHub Pages（全免费静态） |
| 域名 + DNS | Cloudflare（免费 CDN + 防护） |
| CMS | Notion + Super、Obsidian Publish、Astro/Next.js 静态生成 |
| 数据/API | Supabase、Cloudflare Workers、Vercel Functions（按需，无需运维） |
| 表单/分析 | Plausible、Umami、Formspree |

**关键点**：静态站 + Cloudflare 就足够让 GPTBot、PerplexityBot、Google-Extended 抓取。检查 `robots.txt` 不要误封这些 UA。

## 二、GEO 内容层：小团队的主战场

1. **结构化数据**：每个页面加 Schema.org JSON-LD（Article、FAQPage、Organization、HowTo）。这是 AI 解析实体关系最便宜的信号。
2. **事实密度优先**：AI 引用的是"可验证的具体陈述"，不是营销话术。多写数字、日期、定义、对比表。
3. **问答式结构**：H2/H3 用问题句式，段落首句给结论（"答案前置"），方便被摘录。
4. **实体一致性**：品牌名、创始人、产品名在所有平台（官网、LinkedIn、GitHub、知乎、Wikipedia/Wikidata）保持一致。
5. **llms.txt**：在站点根目录放 `llms.txt`（类似 robots.txt 的 LLM 版），列出核心页面和摘要，新兴但成本极低。

## 三、分发与信号（不靠服务器靠平台）

- **被索引源覆盖**：确保内容出现在 Bing（Bing Webmaster Tools 提交）、Google、以及 Perplexity 偏好的来源（Reddit、YouTube、GitHub、维基）。
- **第三方提及**：GEO 很大程度看"别人怎么说你"。争取行业媒体、目录站、问答社区的自然提及。
- **开源/公开资产**：GitHub 仓库、公开数据集、文档站——这些是 AI 训练和检索的高权重源。
- **多平台内容矩阵**：知乎、掘金、Medium、Substack 同步核心观点，增加被检索概率。

## 四、监测（无服务器也能做）

- 手动用 ChatGPT/Perplexity/Kimi 跑固定 prompt 集，记录品牌是否被提及（每周一次，Excel 即可）。
- 用 Google Search Console + Bing Webmaster 看 AI 相关 query 的展现。
- 工具：Profound、Otterly、AthenaHQ（付费），小团队可先用免费额度。
- 自建：Cloudflare Workers + 定时任务调 API 跑 prompt 集，结果存 Supabase。

## 五、小团队的执行优先级

1. **第 1 周**：静态站上线 + JSON-LD + robots.txt 放行 AI 爬虫 + llms.txt
2. **第 2–4 周**：把 10 篇核心内容改写成"答案前置 + 问答结构 + 事实密度高"
3. **持续**：每周 1 次 AI 引擎提及监测 + 每月 2–3 个第三方提及/外链
4. **可选**：用 Workers 做自动监测看板

## 一句话总结

**没有服务器不是障碍——GEO 拼的是内容结构、实体一致性和被引用的信号，这些都能用静态托管 + SaaS + 平台分发零成本做到。** 把省下的运维精力全部投到"写对 AI 友好、值得被引用的内容"上。
