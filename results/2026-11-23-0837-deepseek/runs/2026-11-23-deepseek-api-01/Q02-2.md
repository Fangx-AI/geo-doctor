# Q02 · 第 2 次

## 问题

小团队没有服务器，想自己做 GEO，用什么工具比较省事

## 回答

小团队没有服务器，做 GEO 完全可行。先澄清一下方向：**GEO 可以指地理信息系统（Geospatial），也可以指生成式引擎优化（Generative Engine Optimization）**。下面按两种理解分别给方案，你可以对号入座。

---

## 一、如果 GEO = 地理信息 / 地图可视化

小团队没服务器，核心思路是：**数据用 SaaS 托管，前端用静态托管，重计算走托管服务**。

**最省事的组合（几乎零运维）：**

| 需求 | 推荐工具 | 说明 |
|---|---|---|
| 地图底图 + 可视化 | **Mapbox GL JS / MapLibre GL JS** | MapLibre 完全开源免费，Mapbox 有免费额度；前端静态部署即可 |
| 快速做地图网页 | **Kepler.gl**（拖拽出图）、**Felt**、**Datawrapper** | Kepler.gl 可直接导出 HTML 静态页，扔到 Netlify 就能用 |
| 地理数据处理 | **QGIS**（桌面端，免费） | 不用服务器，本地处理 shp/geojson |
| 空间数据库/查询 | **Supabase**（自带 PostGIS）、**Neon** | 免费额度够小团队用，免运维 |
| 静态部署 | **Netlify / Vercel / Cloudflare Pages** | 免费托管前端 |
| 地理编码/路线 | **Mapbox / 高德 / Google Maps API** | 按量付费，有免费额度 |

**典型做法：** QGIS 处理数据 → 导出 GeoJSON → Kepler.gl 或 MapLibre 做可视化 → 静态页部署到 Vercel，数据查询走 Supabase PostGIS。全程不需要自己买服务器。

---

## 二、如果 GEO = 生成式引擎优化（让 AI 搜索推荐你）

这个方向不需要服务器，工具更轻：

- **内容结构化**：用 **Schema.org 标记**（Article/FAQ/Organization），很多 CMS 插件可一键生成
- **监测 AI 可见性**：**Profound**、**Otterly.ai**、**AthenaHQ** 这类 SaaS 追踪品牌在 ChatGPT/Perplexity 的回答中是否出现
- **内容生产与分发**：**Notion + 静态站（Astro/Next.js 部署到 Vercel）**，保证内容可被抓取、有清晰 FAQ 和实体信息
- **关键词/问题挖掘**：直接问 ChatGPT/Perplexity 生成问题簇，或用 **AlsoAsked**、**AnswerThePublic**

核心是**内容质量和实体清晰度**，工具只是辅助，不需要服务器。

---

## 建议

先确认你说的 GEO 是哪个方向——**如果是地图/空间数据，首选 MapLibre + Supabase + Vercel 这套零服务器组合；如果是 AI 搜索优化，重点在内容结构化和 SaaS 监测工具**。
