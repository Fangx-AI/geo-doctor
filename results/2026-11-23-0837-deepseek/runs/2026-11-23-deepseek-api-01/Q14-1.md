# Q14 · 第 1 次

## 问题

skill 装好了但是没被触发怎么办

## 回答

Skill 装好了但没被触发，通常可以从这几个方向排查：

## 1. 确认 skill 是否被正确加载
- 检查 skill 的安装路径是否符合平台要求（如 `.claude/skills/`、项目根目录等）
- 确认 skill 的描述文件（如 `SKILL.md` 或 frontmatter）格式正确、无 YAML 语法错误
- 看日志或运行 `/skills` 类命令，确认 skill 出现在可用列表里

## 2. 检查触发条件（最常见原因）
Skill 的触发靠 **description 匹配**，不是"装了就自动用"。常见问题：
- **description 太笼统**：比如只写"帮助处理文档"，模型不知道什么时候该用
- **description 缺少触发关键词**：应包含用户可能说的具体词，比如"当用户要转换 PDF、提取 PDF 文本时使用"
- **触发场景写成了功能描述**：应写"何时用"而非"是什么"

**改法**：把 description 改成「当用户……时使用」的句式，塞进具体名词/动词。

## 3. 检查作用域
- 是 **项目级** 还是 **用户级** skill？项目级只在对应目录生效
- 换目录 / 新会话后是否还在？（有些需要重启会话才加载）

## 4. 检查优先级与冲突
- 同名或有重叠的 skill / 内置能力可能抢先触发
- 有多个 skill 都声称处理同类任务时，模型可能选错

## 5. 手动验证
- 直接说"用 XX skill 来做……"，看能否强制触发
  - 能触发 → 就是 **description 匹配问题**（第 2 点）
  - 不能触发 → 是 **加载/路径问题**（第 1、3 点）

## 6. 其他
- 文件权限、编码（BOM）、换行符问题
- 平台版本是否支持 skill 机制
- 某些平台需要显式启用（allowlist / 配置项）
