# Q14 · 第 2 次

## 问题

skill 装好了但是没被触发怎么办

## 回答

Skill 装好了但不触发，通常是**描述（description）没写对**或**触发场景没覆盖到**。按下面顺序排查：

## 1. 先确认 skill 真的被加载了
- 检查存放路径是否正确（如 `.claude/skills/<name>/SKILL.md` 或对应平台的 skills 目录）
- var 文件头部的 `name` / `description` 格式是否合法（YAML frontmatter）
- 重启会话/重新加载，很多平台不会热更新 skill

## 2. 90% 的问题出在 description
模型是靠 `description` 决定要不要调用 skill 的。常见毛病：

- **写得太抽象**："帮助处理文档" → 模型不知道什么时候用
- **没写触发词**：用户实际会说的词（"生成周报"、"转成 PDF"）没出现
- **只写能力不写场景**：应写成"当用户要 X 时使用"，而不是"本 skill 能 Y"

好的写法示例：
```yaml
description: 当用户要求生成/更新周报、整理本周工作、或提到"周报""weekly report"时使用。支持从 git log 和待办中汇总。
```
把**用户会说的原话**和**同义词**都塞进去。

## 3. 触发方式本身的问题
- 有些平台 skill 需要**显式调用**（如 `/skill-name`）而非自动触发
- 自动触发依赖模型判断，模糊请求容易漏；可以先用明确措辞测试："用 xxx skill 帮我……"
- 如果同时装了很多 skill，description 相似会互相竞争，考虑合并或区分关键词

## 4. 快速验证法
1. 用一句**完全匹配 description** 的话测试 → 能触发说明是措辞覆盖问题
2. 用 `/skill-name` 手动调用 → 能跑说明 skill 本身没问题，纯触发问题
3. 看日志/调试输出，确认 skill 列表里有没有它

## 5. 还不行的话
- 把 `description` 改成更"贪婪"的版本（宁可多触发），测试通过后再收窄
- 检查是否有平台对 skill 数量/描述长度的限制导致被截断
- 贴出你的 `SKILL.md` 头部和一句没触发的用户输入，我可以帮你具体改 description

你现在用的是哪个平台（Claude Code / 其他）？description 原文贴一下，能更快定位。
