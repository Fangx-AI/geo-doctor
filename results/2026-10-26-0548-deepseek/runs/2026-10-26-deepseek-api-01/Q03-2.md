# 检查网站能否被 AI 搜索读取的方法

AI 搜索（ChatGPT、Perplexity、Claude、Google AI Overviews、Copilot 等）的抓取和收录检查，可以从以下几个层面入手：

## 一、检查爬虫访问权限

**1. 检查 robots.txt**
- 访问 `你的域名/robots.txt`
- 确认没有误封 AI 爬虫的 User-Agent，常见的有：

| 服务 | User-Agent |
|------|-----------|
| OpenAI | `GPTBot`、`OAI-SearchBot`、`ChatGPT-User` |
| Anthropic | `ClaudeBot`、`Claude-Web`、`anthropic-ai` |
| Perplexity | `PerplexityBot` |
| Google | `Google-Extended`（用于 Gemini 训练） |
| Common Crawl | `CCBot` |
| Apple | `Applebot-Extended` |
| Bytespider (字节) | `Bytespider` |

**2. 检查是否有反爬/防火墙拦截**
- Cloudflare、WAF 可能默认拦截 AI 爬虫，检查 Bot Fight Mode、Bot Management 设置
- 查看服务器访问日志中是否有上述 UA 的请求记录

## 二、验证实际抓取情况

**1. 查看服务器日志**
搜索上述 User-Agent 是否来访过，判断频率和抓取页面。

**2. 用在线工具测试**
- **robots.txt 测试器**：Google Search Console 的 robots.txt 报告
- **模拟抓取**：用 `curl -A "GPTBot" https://你的网址` 测试返回内容
- **Perplexity/ChatGPT 直接问**：在对话里问"site:你的域名 是谁"，看能否返回你的内容

**3. 直接测试 AI 搜索**
- 在 Perplexity 搜索你的品牌名/关键词，看是否引用你的网站
- 在 ChatGPT（联网模式）、Gemini、Copilot 中查询你的网站内容
- 用 `site:你的域名` 语法在支持该语法的 AI 搜索中测试

## 三、检查技术可读性

**1. 内容是否服务端渲染**
- AI 爬虫大多**不执行 JavaScript**（除 Google 较完善）
- 如果内容是 SPA/CSR 渲染，很可能被抓取到空白页
- 检查方法：`curl https://你的网址` 看 HTML 里有没有实际文字内容

**2. 检查 HTML 结构**
- 语义化标签（`<article>`、`<h1>`、`<main>`）
- 结构化数据（Schema.org JSON-LD：Article、FAQPage、Organization 等）
- 清晰的标题层级和正文

**3. 检查响应头**
- `X-Robots-Tag` 是否含 `noindex`
- 是否返回 200（而非 403/429）
- 页面加载速度、重定向链

## 四、内容层面的可引用性

AI 搜索偏爱：
- **有明确答案的段落**（FAQ 式结构）
- **数据、引用、来源**
- **结构化、分点、主题清晰**
- **原创而非纯聚合**
- **作者/机构信息**（E-E-A-T）

## 五、常用免费检查工具

| 工具 | 用途 |
|------|------|
| Google Search Console | 抓取统计、robots 测试、索引状态 |
| Bing Webmaster Tools | 部分 AI 搜索（Copilot）依赖 Bing 索引 |
| curl + UA 模拟 | 快速验证抓取 |
| 服务器日志分析 | 确认 AI 爬虫实际来访 |
| 在线 robots.txt 检查器 | 验证规则生效 |

## 六、关键提醒

1. **Bing 索引很重要**：ChatGPT 搜索、Copilot 部分依赖 Bing，务必提交 Bing Webmaster Tools
2. **Google 索引仍是基础**：AI Overviews、Gemini 依赖 Google 索引
3. **llms.txt** 是新兴约定（非标准），可在根目录提供给 AI 的网站摘要，但目前支持度有限
4. **不要只屏蔽训练爬虫**：`GPTBot` 是训练用，`OAI-SearchBot` 才是搜索用，若希望被 AI 搜索引用，需放行搜索类爬虫
