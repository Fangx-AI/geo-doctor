# Q05 · 第 2 次

## 问题

小团队没有服务器，怎么做 GEO？

## 回答

小团队没有服务器做 GEO（生成式引擎优化，即让 ChatGPT、Perplexity、Google AI Overviews 等 AI 搜索引用你的内容），核心思路是**借船出海**：不需要自建基础设施，把内容托管在 AI 爬虫愿意抓取、且权重高的平台上，同时用低成本工具完成监测。

## 一、先厘清 GEO 对小团队意味着什么

GEO 的本质是让 AI 在生成答案时**引用你、提到你**。AI 引擎的引用来源有几个特点：

- 偏好**结构化、有明确事实**的内容（数据、步骤、对比）
- 偏好**高权重平台**（维基、Reddit、知乎、行业媒体、GitHub、官方文档站）
- 偏好**实体清晰**的品牌（有统一名称、简介、外部提及）

所以没有服务器完全不是障碍——你需要的是**内容分发 + 实体建设 + 监测**。

## 二、内容托管：不建站也能被 AI 抓取

| 平台类型 | 具体选择 | 适合场景 |
|---|---|---|
| 免费建站 | GitHub Pages、Cloudflare Pages、Vercel、Notion + 自定义域名 | 需要品牌官网/文档站 |
| 内容平台 | 知乎、公众号（配合搜一搜）、掘金、Medium、Substack | 行业观点、教程 |
| 问答/社区 | Reddit、Quora、V2EX、Stack Overflow | 长尾问题被 AI 引用 |
| 代码/工具 | GitHub README、Product Hunt、G2 | 工具类产品 |
| 百科/目录 | 维基百科（需满足知名度）、行业目录站 | 实体权威性 |

**关键动作**：在这些平台发布内容时，确保有清晰的**实体信息**（品牌名、一句话定义、官网链接），并使用结构化写法（FAQ、步骤列表、对比表格），AI 更容易抽取。

## 三、实体建设：让 AI 认识你

1. **统一 NAP 信息**：品牌名、简介、链接在所有平台保持一致
2. **Schema 标记**：如果用 GitHub Pages/Notion 建站，加 Organization、FAQPage、Article 的 JSON-LD（免费，纯前端）
3. **外部提及**：争取行业媒体、播客、Newsletter 提到你（哪怕是小媒体），AI 靠"提及密度"判断实体重要性
4. **llms.txt**：在站点根目录放一个纯文本 `llms.txt`，告诉 AI 你的站点结构（无需服务器，静态托管即可）

## 四、监测：低成本验证效果

没有服务器也能做监测，靠**手动 + 免费工具**：

- **手动 prompt 测试**：每周固定 10–20 个目标问题，在 ChatGPT/Perplexity/Kimi/豆包 里问，记录是否提到你、引用哪个来源
- **Google Search Console**（免费）：看 AI Overviews 带来的展现（部分可见）
- **Perplexity 的引用来源**：直接在回答里看它引了谁，反推该去哪些平台布局
- **免费监测工具**：Profound、Otterly 有免费额度；也可用 Google Sheets 手动建追踪表
- **品牌词搜索**：在 AI 引擎里搜品牌名，看 AI 怎么描述你（这是最直接的实体健康度指标）

## 五、一个可执行的最小闭环（2 人团队，每周 5 小时）

1. **周一**：选 5 个目标问题（用户会问 AI 的），在 3 个 AI 引擎里测当前结果，记录引用来源
2. **周二–周三**：针对这些问题，在 1–2 个高权重平台（如知乎 + GitHub Pages）发布结构化答案，埋入实体信息
3. **周四**：在 Reddit/行业社区做 1 次真实互动（回答问题，自然提及产品）
4. **周五**：复测 5 个问题，记录变化；更新追踪表
5. **每月**：检查实体一致性（各平台简介是否统一）、争取 1 次外部提及

## 六、避坑提醒

- **别堆关键词**：AI 引擎看的是语义和事实密度，不是关键词密度
- **别只发自家站**：小站权重低，AI 更信第三方平台，分发比自建更重要
- **别忽略负面**：AI 会引用差评，提前在 G2/Reddit 等平台管理口碑
- **别期待立竿见影**：GEO 是 1–3 个月起效的慢功夫，监测要持续

**一句话总结**：没有服务器，就把 GitHub Pages/Notion 当官网、把知乎/Reddit/GitHub 当内容池、用免费工具 + 手动 prompt 测试做监测，重点打磨"实体一致性 + 结构化内容 + 外部提及"这三件事。
